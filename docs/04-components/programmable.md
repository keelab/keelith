# 可编程工作负载运行时

现代复杂的分布式系统不仅包含“请求-响应”型（Request-Response）API，还大量存在**跨数小时或数天的长时间运行工作流、读写分离下的增量物化视图同步，以及面向多环境动态拓扑切换**。

传统方案通常需要引入巨大的外部依赖（如 Temporal、Cadence 或复杂的 Kafka 流计算）。Keelith 在 `programmable` 模块中原生提供了轻量级、高内聚的运行期原语：**Continuation（持久状态机）**、**Projection（增量投影）**与 **Topology（环境拓扑）**。

---

## 1. 核心三大原语概览

| 原语 | 解决的核心问题 | 典型应用场景 |
| :--- | :--- | :--- |
| **Continuation** | 长时间可暂停、可恢复的多步骤有状态工作流 | 跨日退款审核审批、多阶段支付 Saga、异步合同签名通知 |
| **Projection** | 跨数据源的近实时增量物化视图同步与一致性新鲜度保证 | 订单宽表实时计算、搜索索引同步、读写分离聚合模型 |
| **Topology** | 无需重新编译，运行时声明式切换本地/远程实现 | 单机单元测试（本地内存存储）与生产环境（远程分布式存储）零侵入切换 |

---

## 2. Continuation：持久化长流程执行

传统的 Goroutine 一旦节点重启就会丢失内存栈。Keelith 的 Continuation 将执行状态结构化为带有版本（Revision）、帧序列（Frame）和游标（Cursor）的持久化数据：

```text
               启动任务 (Start)
                     │
                     ▼
           ┌───────────────────┐
           │ 状态: RUNNING      │ 执行第一步 (如: 预扣库存)
           └─────────┬─────────┘
                     │
                     ▼
           ┌───────────────────┐
           │ 状态: WAITING      │ 暂停执行, 持久化当前 Cursor 到数据库
           └─────────┬─────────┘ 释放本地内存与 Goroutine
                     │
       ──────────────┼────────────── 外部异步回调 (数小时或数天后)
                     │
                     ▼
           ┌───────────────────┐
           │ 接收外部信号      │ 校验幂等性 (Idempotent Signal)
           │ (Resume Signal)   │
           └─────────┬─────────┘
                     │
                     ▼
           ┌───────────────────┐
           │ 从 Cursor 恢复    │ 继续执行后续步骤 (如: 确认出库)
           │ 状态: COMPLETED   │
           └───────────────────┘
```

业务逻辑通过纯粹的状态转移函数编写，即便中途发生机房宕机迁移，另一个容器实例也能根据数据库中的 Cursor 状态无缝唤醒并继续执行，天然具备故障自愈能力。

## 3. Projection：增量数据投影与新鲜度约束

在 CQRS（命令查询职责分离）架构中，写库与读库往往是异构的（如 PostgreSQL 写主库，Elasticsearch 提供全文检索）。
Keelith Projection 提供标准化的消费与物化管道：
- **快照基线（Snapshot Baseline）**：从全量快照开始初始化本地读模型。
- **增量应用（Delta Stream）**：持续捕获写库产生的一系列变动事件，并按顺序更新本地聚合视图。
- **持久化检查点（Checkpointing）**：系统重启后自动从最近的 Checkpoint 继续消费，不重放历史。
- **显式新鲜度（`RequireFreshWithin`）**：支持在查询时显式传入时间窗口约束（例如：要求该读模型的新鲜度在 3 秒之内；若检测到延迟超标，可自动降级或直接路由查主库）。

## 4. Topology：不可变环境拓扑计划

在很多微服务中，本地跑单元测试需要 Mock，集成测试需要 Memory 模式，而生产环境需要连接真实的远程集群。以往的做法是写大量的 `if env == "prod"` 分支，极易引入隐蔽 Bug。

Keelith 引入了 **Topology Plan**：
1. 开发者为同一个接口注册两种不同的工厂构造器：
   - `LOCAL`：本地内存或轻量 SQLite。
   - `REMOTE`：生产分布式 PostgreSQL + Redis。
2. 应用启动时，根据不可变的拓扑配置激活指定分支。
3. **延迟安全连接**：未被选中的远程工厂绝对不会建立网络连接，保证在离线测试环境中执行单元测试零外部依赖。

---

## 5. 独立生命周期

> [!TIP]
> **可脱离 HTTP 独立运行**：
> Continuation、Projection 与 Topology 并非绑定在 Web 服务内部的分支。它们完全可以作为纯粹的后台 Worker 独立运行在 Kubernetes Job 或 DaemonSet 中，拥有完全自治的生命周期控制。
